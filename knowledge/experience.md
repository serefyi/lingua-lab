# 實作經驗與後續適用範圍

## 2026-11-20：GitHub Pages 靜態原型

### 已觀察到的經驗

- 目前網站是原生 HTML、CSS、JavaScript，無建置步驟和第三方執行期依賴；對小型互動原型而言，GitHub Pages 可直接部署根目錄。
- 靜態前端無法安全保存秘密金鑰，也不適合直接承擔可信任的 AI 評分。尚未具備可靠評估時，回饋應使用「自我檢查提示」等明確文字，避免讓使用者誤以為得到客觀評分。
- 練習文字屬於使用者可能不想上傳的作答資料。初期只記錄完成次數和時間、留在 `localStorage`，可先提供輕量進度感而不保存作答內容；清除瀏覽器資料時紀錄也會消失。
- `SpeechSynthesis` 的聲音和語言支援依瀏覽器、裝置設定而異。聽力練習需提供可重播方式及文字替代，不能把合成語音當成真人音檔或發音評分。
- 目前是單頁對話框流程。新增偏好選擇時，情境、技能、主題、難度、時長都應在開始練習時讀取當前值，並在結果中說明本次設定，避免控制項只改外觀、不改練習行為。
- 聽力使用 `SpeechSynthesis` 時，文字稿仍應可供檢視和無障礙使用；需把合成音訊、真人錄音、口說錄音／辨識分清楚標示。
- 單次完成記錄要避免提交按鈕重複計數。完成旗標應屬於單次對話狀態；成功後停表、停語音並停用按鈕，空白回答不計入。
- `localStorage` 可能因隱私模式或瀏覽器政策而無法寫入。將讀寫包在 `try/catch`，儲存失敗只顯示提示，不應妨礙完成練習。
- 主題與提示應同時驅動實際材料與題目，而非只在標題顯示主題名稱；各技能材料保持同一主題一致，便於日後換成遠端題庫。
- 九個情境主題各自保存情境、音訊稿、閱讀材料、題目、回應任務與自然說法提示；以同一主題資料支援四種技能，可避免聽讀材料與產出任務各自漂移。
- 難度目前只調整作答提示，尚未調整材料本身的語言複雜度。介面或文件需明確說明這一點，避免誤認為經校準的程度分級。
- 摘要應把已保存的技能累計展示出來，否則進度資料雖在本機、使用者卻看不到。對話框以 Escape 關閉也需要清理計時器和語音播放，避免關閉後背景工作繼續。

### 可重用做法

- 無建置工具的靜態頁面：優先使用原生 JavaScript，新增 npm 或伺服器前先確認是否真的需要。
- 小型個人練習歷程：只保存完成次數、技能與時間等最少資料；不要把自由作答文字放進長期儲存。
- 生成式回饋尚未接入時：採取技能導向的反思問題，清楚說明限制，不以未驗證的分數代表能力。
- 瀏覽器語音功能：保留不依賴語音 API 的替代操作，對語音播放與權限採漸進增強。
- 單頁短練習：設定、定時器、提交、完成紀錄分成小函式；一次提交只寫入完成中繼資料，讓前端失敗時不污染作答隱私。
- 瀏覽器端摘要：呈現總完成數、技能別數量和最近完成日期；資料若只存本機，應在介面清楚標示儲存位置與不保存回答。
- 本機學習摘要雖然不含作答，也應提供明確的清除控制和確認，讓使用者管理這台裝置留下的狀態；清除失敗時需呈現原因且不影響練習。
- GitHub Actions 若出現棄用 runtime 警告，應以官方 action release notes 核對 Node runtime 和額外權限要求，再更新相容主版本；Pages deploy action 更新時也要同步最小必要的 `actions: read` 權限。
- 靜態網站部署很快，可以把 `node --check` 放在上傳 Pages artifact 之前，讓語法錯誤直接阻擋發布；這不取代瀏覽器互動測試或內容品質檢查。
- 對無建置工具的互動原型，可用 Node 內建 `node:test` 與 `vm` 模擬少量 DOM／瀏覽器 API，驗證核心流程而不新增依賴；此類測試能抓狀態與分支回歸，但不能替代真實瀏覽器的排版、無障礙與裝置相容性檢查。

### 未來適用範圍

上述做法適用於此工具的 GitHub Pages 原型及其他不需登入的靜態學習工具。若需要跨裝置紀錄、老師檢視作答、真實口說辨識或 AI 個別評分，需先重新設計資料同意、伺服器端金鑰管理與保存期限，不能直接沿用僅限本機紀錄的設計。
